# Дополнительная UI-проверка Roomly — 26.11.2026

## Цель и критерии

Проверить в работающем интерфейсе каждое правило из [задания](TASK.md), границы диапазонов и ранее описанные дефекты. Кейс считается пройденным, если после ввода и отправки формы виден ожидаемый статус, текст сообщения и ошибка нужного поля. Безопасность проверки: приложение не меняется, внешняя страница и общие стенды не используются, отправка брони не должна порождать сетевой запрос.

## Условия и способ проверки

- Локальная версия `index.html`, `script.js`, `styles.css` открыта как `file://` в настоящих браузерах через Playwright; поля заполнялись, кнопка нажималась или использовался Enter. Внешние запросы (шрифты Google) блокировались.
- Основной прогон: Chromium 145.0.7632.6, часовой пояс `Europe/Moscow`, время браузера зафиксировано на 26.11.2026 12:00 +03:00. Это делает кейсы «сегодня» воспроизводимыми. Дополнительные прогоны: Chromium 145.0.7632.6 и WebKit 26.0.
- 52 основных прогона, 14 повторных в двух движках, 4 адресных проверки: всего 70. Из них 45 дали ожидаемый результат, 25 воспроизвели дефекты или замечания. Повторы нужны для сверки движков, число не означает 70 разных требований.
- Сырые результаты: [основной прогон](evidence/manual-ui-chromium-2026-11-26.json), [кроссбраузерный прогон](evidence/manual-ui-crossbrowser-2026-11-26.json). Адресные проверки описаны ниже.

### Повторная проверка пяти основных дефектов

BUG-01…05 из [основного отчёта](../README.md#дефекты) **подтверждены запуском** на локальной странице в Chromium и WebKit. Для BUG-01 проверены ноль минут; для BUG-02 — сегодня 08:00 при фиксированном времени 12:00; для BUG-03 — появление `img` и изменение заголовка; для BUG-04 — `2.5` участника; для BUG-05 — двойной `@`. В каждом движке позитивный контроль прошёл, поэтому сбой не связан с неработающей формой. Отправка формы не создала сетевых запросов.

### Новый BUG-06: после полуночи принимается вчерашняя дата

- **Приоритет:** средний, вне пяти наиболее значимых дефектов задания. Встречается при долго открытой вкладке, нарушает явный запрет прошлой даты; BUG-02 затрагивает обычный сценарий чаще.
- **Условия и шаги:** часовой пояс браузера `Europe/Moscow`. Открыть форму 26.11.2026 в 23:59, не перезагружать; дождаться 27.11.2026 00:01; выбрать 26.11.2026, 23:00–23:30, заполнить остальные поля корректно, отправить.
- **Ожидается:** ошибка «Дата не может быть в прошлом», брони нет.
- **Фактически:** «Бронирование создано. Средняя, 2026-11-26, 23:00–23:30 · Иван Петров». [Скриншот](evidence/bug-06-midnight-stale-date.png) показывает результат; время браузера после перехода — `Fri Nov 27 2026 00:01:01 GMT+0300`, зафиксировано прогоном.
- **Причина по коду:** `script.js:13` задаёт `dateInput.min` только при загрузке; `validate()` в `script.js:38` сравнивает выбранную дату с устаревшим `min`. Проверено запуском с `page.clock`, а не только чтением кода.

## Ограничения и оставшиеся вопросы

- Эта сессия проверяла локальные файлы. Соответствие опубликованной страницы репозиторию ранее сверено в README, но заново сеть и публичный стенд не проверялись.
- Firefox не перепроверен: для локальной версии Playwright отсутствует исполняемый файл Firefox. Существующий результат в README о восстановлении полей Firefox после F5 остаётся историческим наблюдением, а не подтверждением этого прогона.
- Нативные календарь и пикер времени, реальные мобильные устройства и скринридер не проверялись. UI-сценарии выполнены в headless-браузерах через Playwright.
- Требования не определяют корпоративные домены, правила имени, рабочие часы, шаг времени, горизонт бронирования, формат даты в сообщении, бронь через полночь и старт в текущую минуту. Эти случаи не помечены дефектами без решения аналитика.
- Приложение не менялось. Три автотеста задания сохранены; офлайн Docker-прогон по локальной странице дал `3 passed, 3 xfailed`, exit 0. Два предупреждения относятся к записи кеша pytest в read-only каталог контейнера, на результаты тестов не влияют.
